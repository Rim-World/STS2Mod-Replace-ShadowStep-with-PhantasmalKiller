# 001-E：STS2 模组机制与 Shadow Step / Phantasmal Killer 取证笔记

## 模组基础机制

- STS2 无官方公开 Mod API；游戏内置模组加载器，v0.107.1 起支持 Steam 创意工坊。
- 模组文件：`<id>.json`（必填，清单）+ `<id>.dll`（可选，C# 代码）+ `<id>.pck`（可选，文本/素材）。
- manifest 字段：`id/name/author/description/version/has_pck/has_dll/dependencies/affects_gameplay`；`min_game_version` 与依赖 `min_version` 自 v0.105（2026-05-07 beta）起可用。
- 模组目录：
  - Windows：`<Steam>\steamapps\common\Slay the Spire 2\mods\`
  - macOS：`~/Library/Application Support/Steam/steamapps/common/Slay the Spire 2/SlayTheSpire2.app/Contents/MacOS/mods/`
  - Linux：`~/.steam/steam/steamapps/common/Slay the Spire 2/mods/`
- 游戏数据目录（编译引用 `sts2.dll` / `0Harmony.dll`）：
  - Windows：`data_sts2_windows_x86_64`
  - macOS：`SlayTheSpire2.app/Contents/Resources/data_sts2_macos_{arm64,x86_64}`
  - Linux：`data_sts2_linuxbsd_x86_64`
- 技术栈：C# / .NET 9（`net9.0`），Godot 4.5.1 + Godot.NET.Sdk，Harmony 补丁。游戏自带 0Harmony/MonoMod，官方已支持 macOS arm64。
- 模组入口：`[ModInitializer("ModLoaded")] public static void ModLoaded()`。
- 模组与游戏版本强相关：实践上各模组普遍标注“适配 v0.xxx”（如 RevertAnthony 仅支持 v0.107.1；daoiy 支持 v0.109.0；YuWanCard 按版本对照）。

## 版本与卡牌数据

- default 分支：v0.107.1（2026-06-19，Major Update #2，启用 Steam 创意工坊）。
- public beta 分支：v0.110.0（2026-07-31）；第三方镜像亦见 v0.110.1。v0.110 包含键盘模式、大量平衡调整；静默猎手方面移除 Scare、新增 Sidestep、重做毒疫爆发等，**未改动 Shadow Step**。
- Shadow Step：静默猎手 / 技能 / 稀有 / 1 费；基础文本“Discard your Hand. Next turn, Attacks deal double damage.”；升级后费用 1→0，效果不变。中文社区通行译名“暗影步”（部分资料亦可能称“幻影步”，需用户确认）。
- Phantasmal Killer（STS1）：静默猎手 / 技能 / 稀有 / 1 费；基础文本“Next turn, your Attacks deal double damage.”；升级后 0 费。中文名“幻影杀手”。
- 两者唯一机制差异：Shadow Step 额外“弃掉整手牌”。

## 未来版本兼容要点

- 保持最小补丁面（只碰 OnPlay + Description）。
- 用卡牌 slug 运行时定位类，不硬编码类名。
- 成员缺失时降级（记录日志、禁用补丁），避免游戏崩溃。
- 每次游戏更新后重跑“反编译比对 + 回归”，通常无需改码。
- 联机：`affects_gameplay: true` 的模组要求房间内所有玩家安装。

## v2 补充：整卡替换取证（2026-08-05，基于本机 v0.110.1）

### 本机环境

- 安装路径：`C:\Game\Steam\steamapps\common\Slay the Spire 2`
- `release_info.json`：`version=v0.110.1`（beta，2026-07-31），`branch=v0.110.1`，Godot 4.5.1
- 数据目录：`data_sts2_windows_x86_64\`（含 `sts2.dll` 9.7MB、`sts2.xml` API 注释、`0Harmony.dll`、`GodotSharp.dll` 等）
- 主包：`SlayTheSpire2.pck`（约 1.96GB，Godot pck v3，目录表在文件末尾）
- 用户目录中现存两个改名后的 mods 文件夹（不参与加载），正式需新建 `mods`

### Godot pck v3 格式（可程序化读取/生成）

- 头部：`GDPC` + version(3) + godot 4.5.1 + flags(2) + `file_base`(u64) + `dir_offset`(u64)
- 目录在 `dir_offset`：`file_count`(u32)，每条 = 路径长度(u32)+路径 + 偏移(u64)+大小(u64)+md5(16)+flags(u32)；实际数据偏移 = `file_base + 偏移`
- 可用 Python 脚本列出/抽取 pck 内文件（已实测，脚本见项目工具或可复用）

### 卡牌文本（增量覆盖机制）

- 文件：`localization/<lang>/cards.json`（键值 JSON，支持 BBCode 与 SmartFormat 占位符）
- 关键键：`SHADOW_STEP.title`、`SHADOW_STEP.description`
- Buff 键：`SHADOW_STEP_POWER.title`、`SHADOW_STEP_POWER.description`、`SHADOW_STEP_POWER.smartDescription`（smartDescription 含 `{Amount:...}` 占位符，翻译时不可改动）
- **模组 pck 可只放增量键**：RevertAnthony 的覆盖表仅含改动键（10KB vs 全量 100KB），加载器作为覆盖表合并
- 游戏语言目录：eng/deu/esp/fra/ita/jpn/kor/pol/ptb/rus/spa/tha/tur/zhs/zht；本模组需要的 10 种语言对应 zhs/zht/eng/jpn/kor/esp+spa/ptb/fra/deu/rus（西语两个目录都存在，都放；葡语只有 ptb 巴葡）

### 卡图

- 标准正常卡图：**1000×760**；小变体：**250×190**；全幅（Full art）规格 606×852（本卡不需要）
- 游戏内 Shadow Step：`images/packed/card_portraits/silent/shadow_step.png`（ctex 1000×760）+ `images/atlases/card_atlas.sprites/silent/shadow_step.tres`（AtlasTexture，区域 250×190，引用 `card_atlas_1.png`）
- 替换方式（BaseLib 先例）：Harmony 补丁覆盖 `CardModel.Portrait` / `PortraitPath` / `PortraitPngPath` 三个 getter；模组内放自己的 png（1000×760 + 250×190）
- 模组图标：`mod_image.png` 420×420（创意工坊 <1MB）

### 行为补丁（RevertAnthony 实证）

- `OnPlay` 在卡牌派生类中重写 → 用 Harmony `Prefix(returning false)` 整体替换
- 非重写属性（Rarity/Description 等）→ 补丁 `CardModel` 基类 getter + `Postfix` + `__instance is CardName`
- 修改后需清卡牌缓存：`CardModel._dynamicVars`、`_energyCost` 等（RevertAnthony `ClearAllCanonicalCaches` 参考）
- 卡牌 slug（ModelId）→ 本地化键：`slug.Replace("-","_").ToUpperInvariant()` + `.title/.description`
- 卡牌类命名空间：`MegaCrit.Sts2.Core.Models.Cards`（pck 内有 `src/Core/Models/Cards/*.cs` 源码桩）

### 构建链路

- 代码：.NET 9 + `Godot.NET.Sdk/4.5.1`；引用 `sts2.dll` 与 `0Harmony.dll`（`Private=false`）
- pck：官方模板用 MegaDot/Godot 4.5.1 Mono `--export-pack`；备选 NuGet `BSchneppe.StS2.PckPacker`（纯 dotnet，简单素材场景）
- 参考仓库（当时克隆到本机 `refs/` 目录，该目录未随本仓库提供）：`STS2RevertAnthony`（改卡+本地化覆盖实证）、`BaseLib-StS2`（卡图 getter 补丁）、`ModTemplate-StS2`（模板/尺寸/构建）

### STS2 侧接口（反编译确认）

- `PowerModel.PackedIconPath`（public，小图标 64×64，指向图集 tres）
- `PowerModel.IconPath`（= PackedIconPath）
- `PowerModel.Icon`（= ResourceLoader.Load(PackedIconPath)）
- `PowerModel.ResolvedBigIconPath`（public，大图标 256×256，优先 `images/powers/<id>.png`）
- `PowerModel.BigIcon`（= PreloadManager 按 ResolvedBigIconPath 加载）
- 替换方式：补丁 `PowerModel.PackedIconPath` 与 `ResolvedBigIconPath`（`__instance is ShadowStepPower` / `DoubleDamagePower` 守卫），指向模组 pck 内 `images/powers/phantasmal.png`（64×64）与 `images/powers/big/phantasmal.png`（256×256）
- `DoubleDamagePower` 全库只有 `ShadowStepPower.AfterSideTurnStart` 一处引用（另两处为类型注册/自身），即过渡 Buff 为本卡独占，可以一并改名/换图标
- STS2 现有 `DOUBLE_DAMAGE_POWER.title`：英语 "Double Damage" / 简中 "双倍伤害"；`SHADOW_STEP_POWER.title`：英语 "Shadow Step" / 简中 "暗影步"

### 句号问题根因（实证）

- 模组实际安装文本（读 mods 下的 pck 确认）：
  - zht 卡片描述：`在你的下個回合，你所有的攻擊傷害翻倍`（无句号）
  - kor 卡片描述：`다음 턴 동안 공격 카드가 두 배의 피해를 줍니다`（无句号）
  - kor Buff smartDescription 复数分支：`...줍니다..`（双句号，位于 Buff 描述，不是卡片文本）
- 对比：STS2 原版 zht 描述以「。」结尾、kor 以「.」结尾；替换为 STS1 原文后标点消失——**是源文本本身没有句号，不是游戏渲染问题**。
- 此前“韩语双句号”的说法不准确：双句号在 STS1 韩语 Buff 描述（powers.json）里，卡片文本里一个句号都没有；当时表述混淆了两处。

### 其他排版瑕疵（实际安装文本）

- zhs Buff 描述：`双倍伤害[/gold] 。`（句号前有空格，源自 STS1 原文空格）
- zht Buff 描述：句尾无标点且有尾随空格
- jpn 卡片描述：STS1 的三段 NL 换行已转为 `\n`，正常
- rus Buff smartDescription：复数“хода/ходов”是按俄语语法补全的（STS1 只给了“ходов.”一种）

### 待用户拍板的改进方案

- 语言扩展：新增 ita、pol、tha、tur（STS1 官方文本），最终 14 语言 + esp 双目录。
- 排版策略：A 严格保留 STS1 原文；B（推荐）内容用 STS1、但统一补齐句末标点/修双句号/清理标点前后空格；C 只修明显笔误。等待用户选择后再改。

现象：安装 CorpseExplosionReplacementMod 后游戏启动即弹致命错误；删除该 mod 目录可正常启动。

捕获的 stderr 异常栈（本机诊断日志 `refs/crash-diag/sts2_stderr2.log`，未随本仓库提供）：

```
MegaCrit.Sts2.Core.Models.Exceptions.DuplicateModelException:
ModelDb already contains ID POWER.CORPSE_EXPLOSION_POWER mapped to type
CorpseExplosionReplacementMod.CorpseExplosionPower, but you are trying to map it to
type CorpseExplosionReplacementMod.CorpseExplosionPower.

  at PowerModel..ctor()
  at CorpseExplosionPower..ctor()
```

`ReflectionHelper.GetSubtypesInMods<AbstractModel>()` 自动注册模组自定义 Power
（RevertAnthony 的 `BladeOfInkPower` 即先例），无需手动 Inject。

排除项（日志实证）：Harmony 补丁全部成功应用、mod 初始化正常完成；崩溃发生在更晚的
`ModelDb.Init`。费用缓存补丁、ExtraHoverTips 补丁、RitsuLib info-card schema、
本地化与 pck 均不是本次崩溃原因。

诊断方法备注：直接启动 exe 不走 Steam 初始化，无法复现 mod 加载；临时在游戏目录放
`steam_appid.txt`（2868840）后可完整走到 `ModelDb.Init` 并捕获栈（诊断后已删除该文件）。

## 图鉴问题定案（2026-08-07 用户二分 + 反编译确认）

- 用户实测：107 → 必现；110 → 不现；仅猎人图鉴；仅 CorpseExplosionReplacementMod 开启时触发。
- 根因：default v0.107.1 的 `Outbreak` 与 beta 110.1 完全不同——

- 修复方向 B（如未来要支持 107）：补丁 `CardModel.Type`→Skill 与 `Outbreak.OnUpgrade`→毒+3，

## RitsuLib 实时开关下费用不刷新的根因与方案（2026-08-07）

- 现象：开关切换后名称/卡面/效果实时变化，但费用停留在缓存值：

  `_energyCost` 创建时生效，RitsuLib 切换不会重建缓存。
- 方案 1（简单，覆盖图鉴场景）：在 `RitsuLibModConfig` 的 `SetRitsuLibSettingBool/Value`
  检测到本 mod 开关变化时，反射清空所有 canonical Outbreak 的 `_energyCost`（置 null），
  下次图鉴刷新按当前开关重建费用。
- 方案 2（更强，覆盖已实例化卡牌）：补丁 `CardEnergyCost.GetWithModifiers`，
  开关开启时叠加 `2 - vanillaCanonical`（vanilla 值读 `CardModel` 的
  `<CanonicalEnergyCost>k__BackingField`），并对结果 `Math.Max(0, ...)`；
  已存在于手牌/牌库的实例也能实时变价，但实现更侵入、依赖编译器私有字段。
- 若采用“版本守卫”，107 下费用问题自动消失；110 下按方案 1/2 解决。

## 死亡收割在 default 107 打出后卡住（2026-08-08 已定案）

- 现象：107 下打出死亡收割后卡在画面中央结算区，不造成伤害也不回血；后续卡牌可正常结算，
  但无法结束回合；110 下表现正常。
- 根因（反编译对比实证）：`AttackCommand.FromCard` 的签名跨版本不同——
  - 110：`FromCard(CardModel card, CardPlay? cardPlay)`
  - 107：`FromCard(CardModel card)`（无 cardPlay 参数）
  死亡收割 `OnPlay` 使用的是 110 双参版本；在 107 上首次调用时 CLR 找不到该方法，
  抛 `MissingMethodException`，异步任务故障，卡牌停留在 Play 区，结算流程中断。
  `CreatureCmd.Damage` 的重载同样跨版本不同（110 多一个 `CardPlay? cardPlay` 参数），
  `AttackContext.CreateAsync` 参数也不同（110 收 `CardPlay`，107 收 `CardModel`）。
- 双方都存在的稳定接口：`CreatureCmd.Damage(choiceContext, targets, amount, ValueProp, Creature dealer)`
  5 参重载（107/110 签名一致），可作跨版本兜底；但会失去 AttackCommand 管线的部分语义
  （卡牌来源归属、命中 VFX、部分攻击钩子），需实测确认力量/易伤/死神形态等行为。
- 候选方案：
  A. 跨版本直伤：改用 5 参 `CreatureCmd.Damage` + 手动 VFX（单一源码，兼容 107/110）；
  B. 双版本构建：构建脚本按 `release_info.json` 版本传入条件编译符号，
     107 用 `FromCard(instance)`、110 用 `FromCard(instance, cardPlay)`（语义最完整）；
  C. 与尸爆术一致改为仅支持 beta 110+（`min_game_version=0.110.0` + 分支守卫），107 不加载。
