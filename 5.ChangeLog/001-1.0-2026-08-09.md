# PhantomKillerMod 版本日志（0.1.0 ～ 1.0）

本文件按时间顺序记录 `PhantomKillerMod`（幻影杀手）从最小可用版到 1.0 的版本演进。
每条含七个字段：版本号、时间戳、开发人员反馈、实装更改概括、简略技术细节、
失败经验或实验教训、提交编号。

信息来源：`1.ADR/002`～`004`、`2.PLANS/`、`3.DOCS/001-E`、`3.DOCS/004-T`、`description/`、
`10.OUTPUT/01-构建产物/` 内各版本 manifest 与 pck 条目、仓库 `git log`。

---

## 版本 0.1.0

- **版本号**：0.1.0
- **时间戳**：2026-08-05（构建产物时间 2026-08-06 00:51）
- **开发人员反馈**：按 ADR-002 先交付「能跑通」的最小闭环，等游戏内验证后再决定扩展方向。
- **实装更改概括**：首个可加载版本。仅简体中文；纯色占位卡图；只针对 public beta 0.110.1；
  暗影步的弃牌效果被去掉，卡名/卡面文本/卡图/Buff 名改为幻影杀手，但 Buff 图标与模组图标仍是占位物。
- **简略技术细节**：`ShadowStep.OnPlay` 用 Harmony `Prefix`（`ref Task __result`）整体替换，
  只保留 `PowerCmd.Apply<ShadowStepPower>(…, 1m, …)`；`CardModel` 的 `Portrait` / `PortraitPath` /
  `PortraitPngPath` 三个 getter 前缀替换到 `res://PhantomKillerMod/images/card_portraits/big/phantasmal_killer.png`；
  文本走 pck 增量本地化（当时直接覆盖 `SHADOW_STEP.*` / `SHADOW_STEP_POWER.*`）；
  `build.ps1` 固定「dotnet build → Godot --import → --export-pack → 拷贝到 mods」四步。
  产物：pck 12 个条目（1 个语言目录、占位图 ctex 仅 94～134 字节），DLL 14,848 字节。
- **失败经验或实验教训**：占位卡图与单语言只是临时手段，无法验证「素材替换链路」是否真的可用；
  必须在下一版用真实素材覆盖，否则多语言与图集路径的问题会被掩盖到更晚才暴露。
- **提交编号**：未记录（该版本早于仓库首次提交 `ec525af`，2026-08-08）。

## 版本 0.2.0

- **版本号**：0.2.0
- **时间戳**：2026-08-06
- **开发人员反馈**：用户要求卡名、卡面文本、卡图、Buff 名称与图标全部取自本地正版 STS1（ADR-003）。
- **实装更改概括**：语言从 1 个扩到 11 个目录（10 种语言，`esp` 与 `spa` 同内容）；
  卡图换成 STS1 官方卡图放大版；Buff 名称/描述换成「幻影」，新增 STS1 幻影 Buff 图标（64/256 两种尺寸）；
  模组图标仍为占位。
- **简略技术细节**：从 `desktop-1.0.jar` 提取 `images/1024Portraits/green/skill/phantasmal_killer.png`
  （500×380，LANCZOS 2× 放大到 1000×760）与小图 250×190；图标取 `powers/powers.png` 图集
  `128/phantasmal`（87×86）生成 64×64 与 256×256；新增 `PowerModel.PackedIconPath` /
  `ResolvedBigIconPath` / `Icon` / `BigIcon` 四个补丁，并配合 `PowerIconTextureLoader` 做 pck→内嵌兜底；
  `smartDescription` 用 STS2 的 `{Amount:…}` 语法重组 STS1 的三段描述。
  产物：pck 有 11 个语言目录，DLL 553,984 字节。
- **失败经验或实验教训**：STS1 原文本身缺句末标点（繁中、韩语卡面），直接照搬会让玩家以为渲染出错；
  这属于「素材原样保留」与「排版规范化」的取舍问题，必须显式让用户裁定，不能自作主张。
- **提交编号**：未记录（早于仓库首次提交 `ec525af`）。

## 版本 0.3.0

- **版本号**：0.3.0
- **时间戳**：2026-08-06
- **开发人员反馈**：用户批准「方案 B」（内容用 STS1 原文、排版规范化），并确认新增意大利语、波兰语、
  泰语、土耳其语，`esp` 与 `spa` 写同一份内容。
- **实装更改概括**：语言目录补齐到 15 个（14 种语言）；按方案 B 修正标点与空格；补全波兰语、俄语的
  复数第三形；土耳其语的 `#b` 动态数字转为 `[blue]{}[/blue]`；泰语按语言习惯不加句号。
- **简略技术细节**：从 STS1 jar 读取 14 种语言（`esp` 映射 `spa`），统一转换 `NL → \n`、`#y → [gold]`；
  `smartDescription` 按各语言 STS2 现有风格组装（`choose` / `choose(1)` / `plural` / `plural(ru)`）。
  产物：pck 44 个条目、30 个本地化文件，pck 802,372 字节。
- **失败经验或实验教训**：把「源文本缺标点」误判成「渲染问题」会浪费排查时间；结论是**先比对源文件**
  再怀疑引擎。翻译表必须留存（见 3.DOCS/004-T），否则后续无法复核改动是不是有意为之。
- **提交编号**：未记录（早于仓库首次提交 `ec525af`）。

## 版本 0.4.0

- **版本号**：0.4.0
- **时间戳**：2026-08-06
- **开发人员反馈**：用户希望「不装 RitsuLib 也能用，装了则出现设置页并可实时开关」。
- **实装更改概括**：新增可选的 RitsuLib 设置页（唯一开关「是否将暗影步替换为幻影杀手」，默认开）；
  所有替换补丁改为运行时读取开关，切换无需重启；本地化键从覆盖原键迁移到新增
  `SHADOW_STEP_PHANTOM.*` / `SHADOW_STEP_PHANTOM_POWER.*`，由文本补丁在启用时切键。
- **简略技术细节**：零编译引用互操作——DLL 只带程序集元数据
  `RitsuLib.ModSettingsInterop.ProviderType = PhantomKillerMod.ThirdParty.RitsuLibModConfig`，
  由普通静态类实现 `CreateRitsuLibSettingsSchema` / `Get`/`SetRitsuLibSettingValue` 等方法名契约；
  schema 的 `modId` 统一为 `SingleCardReplacement`，便于多张单卡替换 mod 合并到同一分组；
  状态存 `%LOCALAPPDATA%\SlayTheSpire2\PhantomKillerMod\ritsu_interop_state.json`。
- **失败经验或实验教训**：这套互操作契约没有公开文档，只能照 RitsuLib 源码与 RegentFX 反编译复刻，
  属于「能跑但没有稳定性承诺」的接口；一旦 RitsuLib 改动方法名就会静默失效。
  事后看，为一个可选开关引入这种脆弱耦合，收益不抵维护成本（见 0.5.0）。
- **提交编号**：未记录（早于仓库首次提交 `ec525af`）。

## 版本 0.5.0

- **版本号**：0.5.0
- **时间戳**：2026-08-07
- **开发人员反馈**：用户决定不与 CustomCardBalance 兼容，改为自身加固；同时移除 RitsuLib 相关集成。
- **实装更改概括**：所有本地化键加模组专属前缀（本 mod 为 `RE_SHADOW_STEP_PHANTOM*`，同批三模组共 75 个
  JSON 文件）；删除 `ThirdParty/RitsuLibModConfig.cs`、程序集元数据与设置页；补丁启用判断简化为
  固定 `ModConfig.IsReplaceShadowStepEnabled => true`。
- **简略技术细节**：改键同时改补丁里的 `new LocString("cards"/"powers", "RE_…")` 字面量，
  保证 pck 与 DLL 两侧一致；移除后 DLL 内不再有 `STS2RitsuLib.*` 引用；
  验证方式为「pck 全部为新键（旧键 0）+ DLL 无互操作元数据 + beta 110.1 启动回归无异常」。
- **失败经验或实验教训**：第三方 mod（CustomCardBalance）自带塔1 卡并用同名 `REAPER.*` 键，
  合并本地化表时会覆盖我方文本，表现为卡面多出「消耗」行。教训是**模组本地化键必须全局唯一**，
  不能依赖加载顺序。另：可选依赖的真实收益远小于其隐性维护成本。
- **提交编号**：未记录（早于仓库首次提交 `ec525af`）。

## 版本 1.0

- **版本号**：1.0
- **时间戳**：2026-08-09（版本统一动作记录于 2026-08-08，最终构建 2026-08-09 04:29，Release 2026-08-09）
- **开发人员反馈**：用户要求统一版本号并清理源码目录中的历史产物，作为正式版发布。
- **实装更改概括**：三个同批 mod 的 manifest 版本统一为 `1.0`（DLL 程序集版本本就是默认 `1.0.0.0`）；
  删除源码根目录旧 `*.dll` / `*.pck` / `*.pdb` 与 `ThirdParty/` 残留；剔除冗余资源后重新构建；
  在 GitHub 发布 v1.0 Release（源码包 + 运行包）。
- **简略技术细节**：`min_game_version` 保持 `0.107.1`；重新构建后 pck 仍为 44 个条目，
  但 `mod_image.png` 由 206,110 字节换成 133,601 字节的正式图标（ctex 177,448 → 111,252），
  pck 由 803,300 字节降到 664,612 字节；DLL 556,032 字节。
  `PhantomKillerMod 正式版v1.0` 与 `PhantomKillerMod v6（剔除冗余资源，最终1.0版本）` 两份产物
  逐字节一致（pck md5 `0218dfdbb26dc37a069185dbaf52ee8c`）。
- **失败经验或实验教训**：源码根目录混放构建产物会让「哪份是现役源码」变得不可判断，
  也让源码包体积虚高（`PhantomKillerModSourceCode.zip` 含 `.godot/` 缓存，3.2 MB）；
  此类文件应当从源码树剥离，只经 Release 分发。
- **提交编号**：仓库 tag `v1.0` → 提交 `25c3da6`（2026-08-08 20:01，Add mod resource folders）；
  其后 `8eb7898`（2026-08-09 16:47，按本地源码重建仓库内容）与 `ff0a66d`（2026-08-11 18:09，README 修订）
  为仓库同步提交，均晚于 Release。
