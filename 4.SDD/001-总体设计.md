# 001 总体设计

- 文档版本：1.0（对应 mod 版本 1.0）
- 最后更新：2026-11-01（仓库整理时按现役源码重述，未改动代码）
- 适用工程：`9.SRC/PhantomKillerMod/`

## 1. 目标

把《杀戮尖塔 2》静默猎手的卡牌 **Shadow Step（暗影步）** 整卡替换为《杀戮尖塔 1》的
**Phantasmal Killer（幻影杀手）**，具体为：

1. 机制：去掉「弃掉整手牌」，只保留「下回合攻击造成双倍伤害」。
2. 表现：卡名、卡面文本、卡图、Buff 名称与图标全部换成幻影杀手。
3. 依赖：不依赖任何基础 mod（manifest `dependencies: []`），只依赖游戏自带的 Harmony。
4. 版本：同时支持 default 107 与 public beta 110；不针对单一小版本写死判断。
5. 语言：覆盖 STS2 的 15 个语言目录（14 种语言，`esp` 与 `spa` 同内容）。

产物为 `<id>.json` + `<id>.dll` + `<id>.pck` 三件套，安装到游戏的 `mods/PhantomKillerMod/`。

## 3. 工程结构（现役源码实测）

```
9.SRC/PhantomKillerMod/
├─ PhantomKillerMod.csproj        # 构建定义（含 3 个内嵌 PNG 的 EmbeddedResource 声明）
├─ PhantomKillerMod.json          # mod 清单
├─ project.godot                  # Godot 工程（config_version=5）
├─ export_presets.cfg             # 导出预设（export_filter="resources"，不加密）
├─ build.ps1                      # 构建脚本：build → import → export-pack → 拷贝
├─ ModEntry.cs (+ .uid)           # 入口与资源路径常量
├─ ModConfig.cs (+ .uid)          # 补丁开关（当前恒为 true）
├─ PortraitTextureLoader.cs (+ .uid)
├─ PowerIconTextureLoader.cs (+ .uid)
├─ Patches/
│  ├─ ShadowStepOnPlayPatch.cs (+ .uid)   # 打出效果
│  ├─ CardPortraitPatches.cs (+ .uid)     # 卡图三个 getter
│  ├─ PowerIconPatches.cs (+ .uid)        # Buff 图标四个 getter
│  └─ ShadowStepTextPatches.cs (+ .uid)   # 卡名/卡面/Buff 文本五个 getter
├─ assets/                        # 内嵌兜底 PNG（3 张，同时被 csproj 内嵌）
└─ PhantomKillerMod/              # pck 内资源的工程侧目录（导出后成为 res:// 相对路径）
   ├─ mod_image.png
   ├─ images/card_portraits/{phantasmal_killer.png, big/phantasmal_killer.png}
   ├─ images/powers/{phantasmal.png, big/phantasmal.png}
   └─ localization/<15 个语言目录>/{cards.json, powers.json}
```

`*.uid` 文件是 Godot 4.4+ 的资源 UID 映射，必须与对应脚本一起保留。

## 4. 模块划分与职责

| 模块 | 文件 | 职责 |
|---|---|---|
| 入口 | `ModEntry.cs` | `[ModInitializer("ModLoaded")]` 标记静态入口；创建 `Harmony("PhantomKillerMod")` 并 `PatchAll`；导出三个 `res://` 资源路径常量 |
| 开关 | `ModConfig.cs` | `IsReplaceShadowStepEnabled => true`；所有补丁的统一总闸（RitsuLib 版曾为可写，v0.5.0 起为只读常量） |
| 行为补丁 | `Patches/ShadowStepOnPlayPatch.cs` | `Prefix` 整体替换 `ShadowStep.OnPlay` |
| 卡图补丁 | `Patches/CardPortraitPatches.cs` | 替换 `CardModel.PortraitPngPath` / `Portrait` / `PortraitPath` |
| 图标补丁 | `Patches/PowerIconPatches.cs` | 替换 `PowerModel.PackedIconPath` / `ResolvedBigIconPath` / `Icon` / `BigIcon`，仅对 `ShadowStepPower` 生效 |
| 文本补丁 | `Patches/ShadowStepTextPatches.cs` | `Postfix` 改写 `CardModel.TitleLocString` / `Description` 与 `PowerModel.Title` / `Description` / `SmartDescription`，指向 `RE_*` 键 |
| 纹理加载 | `PortraitTextureLoader.cs`、`PowerIconTextureLoader.cs` | 优先 `ResourceLoader.Load` 读 pck；失败回退 DLL 内嵌 PNG；结果静态缓存 |
| 资源层 | `PhantomKillerMod/`（导出进 pck） | 15 个语言目录的 `cards.json` / `powers.json`、卡图与图标、mod 图标 |

## 5. 补丁策略

### 5.1 行为：整体替换而非增量

`ShadowStep.OnPlay` 是派生类中重写的虚方法，`Prefix` 返回 `false` 直接接管返回值（`ref Task __result`），
从而彻底跳过原实现中的 `CardCmd.Discard(手牌)`，只保留：

```csharp
await PowerCmd.Apply<ShadowStepPower>(
    choiceContext, instance.Owner.Creature, 1m, instance.Owner.Creature, instance);
```

费用（1 费，升级后 0 费）与稀有度不改——与 STS1 幻影杀手一致，因此无需额外补丁。

### 5.2 表现：getter 级 `Prefix` 替换

卡图与图标都通过「替换 getter 的返回值」实现，而不是覆盖游戏资源文件：

- 卡图有三个入口（`PortraitPngPath` 返回原图路径、`PortraitPath` 返回图集切片路径、`Portrait` 返回纹理对象），
  三者全部指向模组内同一张 1000×760 PNG，保证卡组、手牌、奖励、图鉴等入口一致。
- Buff 图标同理覆盖「路径」与「纹理」两条链，并区分 64×64 小图与 256×256 大图。
- 所有补丁都带 `__instance is ShadowStep` / `__instance is ShadowStepPower` 的**实例守卫**，
  不影响其它任何卡牌与 Buff。

### 5.3 文本：`Postfix` 换键，而非覆盖原键

文本补丁不修改游戏原有的 `SHADOW_STEP.*` / `SHADOW_STEP_POWER.*`，而是在 getter 返回后把 `LocString`
的键替换成模组自带的新键。这样：

- 模组卸载后原版文本完好，无需清理；
- 不会与其它改同卡或同键的 mod 发生「谁覆盖谁」的问题（历史上正因 `REAPER.*` 与
  CustomCardBalance 撞键才引入 `RE_` 前缀，见 3.DOCS/001-E）。

## 6. 本地化键约定

| 键 | 命名空间 | 用途 |
|---|---|---|
| `RE_SHADOW_STEP_PHANTOM.title` | `cards` | 卡名 |
| `RE_SHADOW_STEP_PHANTOM.description` | `cards` | 卡面文本 |
| `RE_SHADOW_STEP_PHANTOM_POWER.title` | `powers` | Buff 名称 |
| `RE_SHADOW_STEP_PHANTOM_POWER.description` | `powers` | Buff 描述（静态） |
| `RE_SHADOW_STEP_PHANTOM_POWER.smartDescription` | `powers` | Buff 描述（带数值，SmartFormat） |

约定要点：

1. `RE_` 是本模组（Replacement 系列）专属前缀，**全部键必须带前缀**，防止与游戏原生键或第三方 mod 撞键。
2. 语言目录固定 15 个：`deu/eng/esp/fra/ita/jpn/kor/pol/ptb/rus/spa/tha/tur/zhs/zht`；
   `esp` 与 `spa` 写同一份西班牙语内容（游戏两个目录都存在）。
3. 文本使用 STS2 的 BBCode 子集：`[gold]…[/gold]`（原 STS1 的 `#y`）、`[blue]{}[/blue]`
   （原 STS1 的 `#b` 动态数字，泰语/土耳其语出现过）；STS1 的 `NL` 换行标记转成 `\n`。
4. `smartDescription` 的占位符语法按语言区分：`{Amount:choose:…|…}`（zhs/zht/jpn/kor/tha）、
   `{Amount:plural:…|…}`（eng/esp/spa/ptb/fra/deu/ita/pol/tur）、`{Amount:plural(ru):…|…|…}`（rus）。
   **翻译时不得改动占位符结构**，只改可见文本。
5. 逐语言的最终文本与排版裁定见 [3.DOCS/004-T-幻影杀手翻译对照表.md](../3.DOCS/004-T-幻影杀手翻译对照表.md)。

## 7. 数据流

```
游戏启动
  └─ ModManager 读取 mods/PhantomKillerMod/PhantomKillerMod.json（has_dll/has_pck 均为 true）
      ├─ 加载 pck → localization/*.json 作为「增量覆盖表」并入游戏本地化表
      └─ 加载 dll → ModEntry.ModLoaded()
            └─ Harmony.PatchAll()：应用 13 个补丁（1 行为 + 3 卡图 + 4 图标 + 5 文本，文本均为 Postfix）
游戏内任一 ShadowStep 实例
  ├─ 渲染：TitleLocString / Description → RE_SHADOW_STEP_PHANTOM.*
  │        Portrait / PortraitPath / PortraitPngPath → res://PhantomKillerMod/images/...
  └─ 打出：OnPlay 被 Prefix 接管 → 只施加 1 层 ShadowStepPower（无弃牌）
        战斗内该 Power：Title/Description/SmartDescription → RE_SHADOW_STEP_PHANTOM_POWER.*
                        Icon/BigIcon/PackedIconPath/ResolvedBigIconPath → res://PhantomKillerMod/images/powers/...
资源加载顺序：pck 内 PNG → 失败则 DLL 内嵌同图（assets/*.png，经 csproj EmbeddedResource）
```

补丁数量按现役源码点数：`ShadowStepOnPlayPatch` 1 个、`CardPortraitPatches` 3 个、
`PowerIconPatches` 4 个、`ShadowStepTextPatches` 5 个，共 13 个补丁类（文本 5 个均为 `Postfix`）。

## 8. 可见性与兼容设计

| 维度 | 设计 | 依据 |
|---|---|---|
| 影响范围 | 仅 `ShadowStep` 一个卡牌类与 `ShadowStepPower` 一个 Buff；不改卡池、不改稀有度、不改费用 | 补丁的实例守卫 |
| 过渡 Buff | `DoubleDamagePower` 保持原名原图标（用户明确要求） | ADR-003 后果段 |
| 存档 | 不新增自定义模型、不写存档字段；「影响存档」仅表现为同一张卡在历史记录里显示为新名新图 | manifest 无自定义模型；3.DOCS/003-T |
| 多人 | `affects_gameplay: true`，要求房间内所有玩家安装同版本 | manifest |
| 版本 | 不硬编码游戏版本判断，靠 `min_game_version` 与补丁点稳定；107/110 差异未触及本 mod 的补丁点 | 3.DOCS/001-E |
| 与其它 mod | 不依赖 BaseLib；文本用独立 `RE_` 键，避免与同卡改写类 mod 撞键 | ADR-001、3.DOCS/001-E |
| 不兼容范围 | 不保证盗版、修改版、移动版、老旧版本、冷门/次级 mod | description/幻杀_中文.md 第 ⑤ 节 |

## 9. 异常处理与失败降级

| 位置 | 行为 |
|---|---|
| `ModEntry.ModLoaded` | 整体 `try/catch`：补丁失败只写 `Log.Error`，不向上抛出，避免拖垮游戏启动 |
| `PortraitTextureLoader.Get` | pck 加载失败 → `Log.Warn` → 从 DLL 内嵌资源解 PNG → 成功则 `ImageTexture.CreateFromImage`；仍失败 → `Log.Error` 并返回缓存值（调用方按非空使用） |
| `PowerIconTextureLoader.Load` | 同上，且 64/256 两张图各自独立降级 |
| 补丁守卫 | 实例类型不符或开关关闭时返回 `true`，交回原实现（不改变行为） |

已知薄弱点（如实记录，未改动代码）：

- `PortraitTextureLoader.Get()` 与 `PowerIconTextureLoader.Get64/Get256()` 的返回类型为非空
  `Texture2D`，pck 与内嵌资源同时失败时实际可能返回 `null`（用了 `!` 抑制），
  调用方（卡图/图标 getter）会把它当作有效纹理返回给游戏，存在空引用风险。
- 没有游戏版本探测或成员存在性检查：若未来版本删除/重命名 `ShadowStep` 或相关 getter，
  Harmony 在 `PatchAll` 阶段会抛异常，被 `ModLoaded` 的 `catch` 吞掉并记日志，模组退化为「无效果」，
  不会崩溃，但也没有更明确的宿主提示。

## 10. 构建与测试方案

### 10.1 构建（`build.ps1`，四步）

1. `dotnet build PhantomKillerMod.csproj -c Debug`；
2. `Godot --headless --import --path <root>`：生成 `.import` 与 `.godot/imported/*.ctex`；
3. `Godot --headless --export-pack "Windows Desktop" <mods>/PhantomKillerMod/PhantomKillerMod.pck --path <root>`；
4. 拷贝 `.dll`、`.pdb`、`PhantomKillerMod.json` 到 `mods/PhantomKillerMod/`。

导出预设 `export_filter="resources"`（只导出被引用的资源），不加密 pck。

### 10.2 测试方案（来自 2.PLANS/001-G 阶段 3，属计划内容）

- 模组正常加载、日志无报错；
- 打出后手牌全留、弃牌联动（Sly 等）不再触发、下回合攻击双倍；
- 升级后 0 费；
- 卡名/卡面/卡图在卡组、手牌、奖励、图鉴、战斗内一致；
- Buff 名称与图标正确；
- 逐一切换 15 个语言目录核对文本；
- 读档、新开一局、商店/复制/转化等生成路径；
- 与 BaseLib、ModConfig 等常用模组共存冒烟测试。

### 10.3 实际测试记录

文档中可查到的测试结论只有「构建安装成功、启动回归无异常、指定语言文本已核对」
