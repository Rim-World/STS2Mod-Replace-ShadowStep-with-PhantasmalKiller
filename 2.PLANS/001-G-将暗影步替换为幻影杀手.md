# 001-G：将杀戮尖塔2「Shadow Step」整卡替换为「Phantasmal Killer」

## 1. 目标（v2，已按用户确认更新）

制作杀戮尖塔2（STS2）模组 `PhantomKillerMod`，把静默猎手卡牌 **Shadow Step（暗影步）** 整卡替换为杀戮尖塔1的 **Phantasmal Killer（幻影杀手）**：

- 机制：去掉“弃掉整手牌”，只保留“下回合攻击造成双倍伤害”。
- 卡名、卡面描述、卡图全部替换为幻影杀手。
- 文案支持 10 种语言：简体中文、繁体中文、英文、日语、韩语、西班牙语、葡萄牙语、法语、德语、俄语（用户后续提交对照表）。
- 版本顺序：**先只做 public beta v0.110.1（已在本机确认安装），完成并测试后**，再适配 default v0.107.1。
- 平台：仅 Windows（macOS 需求已撤销）。
- 分发：本地测试通过后，用户自己通过 Steam 创意工坊上传。
- 长期目标：尽可能避免“每个版本专门适配”。

## 2. 已确认的关键事实（v2 调研结论）

### 2.1 目标卡数据（v0.110.1 实机取证）

| 项目 | 现状（Shadow Step） | 目标（Phantasmal Killer） |
|---|---|---|
| 卡名键 | `SHADOW_STEP.title` | 替换为新名字 |
| 描述键 | `SHADOW_STEP.description` | 去掉弃牌句 |
| 费用/稀有/类型 | 1费 / 稀有 / 技能 | 不变 |
| 升级 | 费用 1→0 | 不变（与 PK+ 一致） |
| 机制差异 | 仅“弃掉整手牌” | 无弃牌 |

### 2.2 文本与本地化机制（已实证）

- 游戏文本位于 `localization/<语言>/cards.json` 等键值 JSON（支持 `[gold]...[/gold]` 等 BBCode 与 `{占位符}`）。
- **模组可以只放增量键覆盖**：RevertAnthony 模组的 `localization/eng/cards.json` 只有被改动的约 200 个键（10KB），而游戏全量文件约 100KB——模组加载器会把模组表作为覆盖表合并。
- 因此本模组只需在 pck 里放：
  - 每种语言一个 `localization/<lang>/cards.json`，仅含 `SHADOW_STEP.title` 与 `SHADOW_STEP.description`；
  - 可选（建议做）：`localization/<lang>/powers.json`，覆盖战斗 Buff 名 `SHADOW_STEP_POWER.title`（见 2.5）。
- 语言目录（游戏自带）：`eng/deu/esp/fra/ita/jpn/kor/pol/ptb/rus/spa/tha/tur/zhs/zht`。
  - 用户需要的 10 种语言对应：`zhs`（简中）、`zht`（繁中）、`eng`、`jpn`、`kor`、`esp` 与 `spa`（西语两个目录都存在，稳妥起见两个都放）、`ptb`（游戏只有巴西葡语，无欧葡）、`fra`、`deu`、`rus`。

### 2.3 卡图机制（已实证）

- 卡牌正常卡图标准尺寸：**1000×760**；小尺寸变体：**250×190**（用于奖励/图鉴等效率场景）。
- 游戏内 Shadow Step 卡图路径：`images/packed/card_portraits/silent/shadow_step.png`（1000×760）+ 图集小图 `images/atlases/card_atlas.sprites/silent/shadow_step.tres`（区域 250×190）。
- 替换路径（社区标准）：BaseLib 的 `CustomCardModel` 通过 Harmony 补丁覆盖 `CardModel.Portrait` / `PortraitPath` / `PortraitPngPath` 三个 getter。本模组不依赖 BaseLib，**自己写同样的三个 getter 补丁**，让 `ShadowStep` 实例返回模组 pck 内的新图路径。
- 模组图标：`mod_image.png` 420×420（创意工坊要求 <1MB）。

### 2.4 行为补丁机制（参考 RevertAnthony 实证）

- 卡牌行为是 C# 类 `ShadowStep`（命名空间 `MegaCrit.Sts2.Core.Models.Cards`，源码桩在 pck 的 `src/Core/Models/Cards/ShadowStep.cs`）。
- `OnPlay` 是**在派生类中重写的方法**，用 Harmony `Prefix(returning false)` 整体替换：保留“触发动画 + 施加 `ShadowStepPower`”命令，去掉弃手牌命令。具体命令序列以反编译 v0.110.1 的 `sts2.dll` 为准。
- 费用/升级等无需改动（现状已符合 PK）。

### 2.5 战斗 Buff（需要用户确认的可选改动）

- 打出 Shadow Step 后获得的 Buff 键为 `SHADOW_STEP_POWER.title/.description/.smartDescription`，目前名称就是“Shadow Step / 暗影步”。
- 建议顺带把 Buff 名改为 PK 风格的“Phantasmal / 幻影”（10 语言），使整卡替换更完整；Buff 图标默认保留原样（也可另提供图标）。

### 2.6 构建链路（已实证）

- 模组 = `<id>.json`（清单，必填）+ `<id>.dll`（代码）+ `<id>.pck`（素材/文本，本模组必需）。
- 代码构建：.NET 9 + `Godot.NET.Sdk 4.5.1`，引用游戏数据目录的 `sts2.dll` / `0Harmony.dll`（本机路径：`C:\Game\Steam\steamapps\common\Slay the Spire 2\data_sts2_windows_x86_64\`）。
- pck 构建：官方模板用 **MegaDot / Godot 4.5.1 Mono** 执行 `--export-pack`；另有 NuGet 包 `BSchneppe.StS2.PckPacker` 可尝试纯 dotnet 生成 pck（简单素材场景），失败再装 Godot。
- 安装目录：`C:\Game\Steam\steamapps\common\Slay the Spire 2\mods\PhantomKillerMod\`（注意：用户当前目录里有两个改名后的 mods 文件夹，正式模组目录需新建标准 `mods`）。

## 3. 最终架构

```
PhantomKillerMod/
├─ PhantomKillerMod.json                     # 清单：has_dll=true, has_pck=true, affects_gameplay=true
├─ PhantomKillerMod.dll                      # Harmony 补丁
└─ PhantomKillerMod.pck
   ├─ localization/
   │  ├─ zhs/cards.json (+ powers.json)      # 仅覆盖 SHADOW_STEP.* 键
   │  ├─ zht/...  eng/...  jpn/...  kor/...
   │  ├─ esp/...  spa/...  ptb/...  fra/...  deu/...  rus/...
   ├─ images/card_portraits/
   │  ├─ phantasmal_killer.png               # 1000×760 正常卡图
   │  └─ small/phantasmal_killer.png         # 250×190 小图（自动缩放生成）
   └─ mod_image.png                          # 420×420 模组图标
```

DLL 内补丁清单：

1. `ShadowStep.OnPlay`（Prefix 替换）：动画 + 施加 `ShadowStepPower`，无弃牌。
2. `CardModel.Portrait` / `PortraitPath` / `PortraitPngPath`（Postfix，仅 `__instance is ShadowStep`）：返回模组 pck 内新图路径/纹理。
3. 启动版本探测：若 v0.110.1 的成员签名与预期不符（例如未来版本改类名），写日志并禁用补丁，不崩溃。

## 4. 实施阶段

### 阶段 0：等待用户素材（可并行推进阶段 1）

需要用户提交：

1. **卡图**：1000×760 PNG（必须）。可另附 250×190 小图（可选，没有则自动缩放）。推荐同时提供 420×420 模组图标（可选，没有则从卡图裁剪）。
2. **十语言对照表**（动工时提交，我会先给 Excel/CSV 模板）：
   - 每语言：卡名（title）、卡面描述（description）、Buff 名（若同意改名）。
   - 说明：描述若不需要高亮，可以完全不用 BBCode；若使用 `[gold]...[/gold]`，所有语言必须一致使用。
3. **确认 Buff 改名**：默认同意（Phantasmal / 幻影）；Buff 图标默认不换。

### 阶段 1：取证与脚手架（0.5~1 天，110.1）

- 反编译 `data_sts2_windows_x86_64\sts2.dll`（ILSpy/ilspycmd），确认：
  - `ShadowStep.OnPlay` 完整命令序列（弃牌命令与双倍伤害 Power 命令）；
  - `CardModel.Portrait/PortraitPath/PortraitPngPath` 的定义与 ShadowStep 是否重写；
  - 清缓存/克隆相关逻辑（若卡牌属性被缓存，需要像 RevertAnthony 一样清 `_dynamicVars`/`_energyCost`）。
- 搭工程：参照 ModTemplate-StS2 的 Empty/Content 模板，去掉 BaseLib 依赖；配置 `Sts2Path=C:/Game/Steam/steamapps/common/Slay the Spire 2`、`GodotPath`（或 PckPacker）。
- 写 PowerShell 构建脚本：编译 → 生成 pck → 拷贝到 `mods\PhantomKillerMod\`。

### 阶段 2：实现 110.1（2~4 天）

- 代码：OnPlay 补丁 + 三个 Portrait getter 补丁 + 版本探测。
- 素材：用户卡图入库（自动生成小图）；本地化覆盖表入库（用户对照表 → 生成各语言 JSON）。
- 构建并安装到本机，游戏内自检。

### 阶段 3：本地测试 110.1（1~2 天）

检查清单：

- 模组正常加载，无报错；
- 打出 Shadow Step：**手牌全部保留**，弃牌联动（Sly 等）不再触发，下一回合攻击双倍；
- 升级后 0 费；
- 卡名/卡面文案/卡图在卡组、手牌、奖励、图鉴、战斗内全部显示为新内容；
- Buff 名（若启用改名）正确；
- 简体/繁体/英文/日/韩/西（esp+spa）/葡/法/德/俄 逐一切换语言验证；
- 读档、新开一局、商店/复制/转化等生成路径；
- 与 BaseLib、ModConfig 等常用模组共存冒烟测试。

### 阶段 4：适配 default v0.107.1（110 通过后再做）

- 用户在 Steam 切回 default 分支；拷贝 107.1 的 `sts2.dll`/`0Harmony.dll` 到本机 `refs/` 参考目录（未随本仓库提供）。
- 反编译比对：ShadowStep、CardModel 相关成员是否一致；本地化键/卡图路径是否一致。
- 一致 → 同一份产物直接重验；不一致 → 修代码/补丁或按分支出双版本。
- 测试清单与阶段 3 相同。

### 阶段 5：交付与发布（0.5 天）

- 产出 `dist/`：json + dll + pck + README（安装路径、支持版本、联机说明、更新记录）+ `workshop.json` 模板 + `mod_image.png`。
- 用户自行用官方 [sts2-mod-uploader](https://github.com/megacrit/sts2-mod-uploader) 上传；我提供字段建议，不上传。

### 阶段 6：未来版本维护策略

- 每次游戏大版本更新：重跑“反编译比对 + 阶段 3 回归脚本”。
- 由于补丁面极小（一张卡的 OnPlay + 三个图 getter + 两个文本键），预计多数更新无需改码；改动量通常为 10~30 分钟级。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 107 与 110 的 API/成员签名不一致 | 需要双构建 | 先反编译比对；优先做 110，107 阶段再定；必要时按分支出两个包并在 README 说明 |
| pck 需要 Godot/MegaDot 导出 | 构建环境变重 | 先试 `BSchneppe.StS2.PckPacker` 纯 dotnet 方案；不行再装 MegaDot 4.5.1 |
| 卡图在部分界面仍显示原图（小图/图集路径未覆盖） | 替换不完整 | 同时补三个 getter + 小图文件；测试清单覆盖奖励/图鉴等入口 |
| 未来更新改类名/成员名 | 模组失效 | 版本探测 + 失败降级（不崩溃、有日志） |
| 联机一致性 | 队友不同步 | `affects_gameplay: true`，README 注明所有玩家需安装 |
| 本地化键在 107/110 间变化 | 文案失效 | 107 阶段重新核对键与覆盖表 |
| 卡图版权/素材来源 | 发布风险 | 用户自行确认素材来源（自制/授权最稳妥；若用 STS1 官方卡图需自行确认 Mega Crit 政策） |
